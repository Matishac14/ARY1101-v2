Resumen Ejecutivo

El directorio ha solicitado evaluar la viabilidad de migrar nuestra infraestructura on-premise a la nube. Hemos diseñado, desplegado y validado una Prueba de Concepto (PoC) en AWS que demuestra que podemos erradicar las caídas de servicio, aislar nuestras cargas de trabajo y optimizar los costos migrando hacia un modelo operativo escalable.

TechNova: El Desafío del Crecimiento

  • Contexto de Crecimiento: E-commerce 100% online con un crecimiento explosivo del 60% en ventas los últimos 18 meses, superando la capacidad del hardware base.
  • Limitación On-Premise: Operación basada en servidores VMware en datacenter arrendado. El equipo de TI está sobrepasado administrando hardware manualmente.
  • Impacto Financiero: En el último año sufrimos 9 eventos de caída sumando 14 horas de downtime (caídas de 45m a 3h en picos de demanda).
  • Pérdida Directa: Cada hora inoperativa cuesta un 3% de las ventas diarias promedio no recuperables.

Topología Actual (AS-IS): El Cuello de Botella

Análisis de Riesgos

  • Single Point of Failure: Toda la arquitectura descansa en un solo servidor físico/VM. Si los recursos se saturan, la tienda completa cae.
  • Falta de Balanceo: Todo el tráfico de Internet golpea directamente el servidor, sin mecanismos para distribuir la carga.
  • Riesgo de Datos: La base de datos MySQL cohabita en la misma máquina que los componentes expuestos a Internet.

Propuesta de Valor Cloud

Resiliencia (ALB)

Desacoplamos el monolito. El Application Load Balancer absorbe los picos de tráfico de Black Friday y distribuye las cargas inteligentemente.

Operación (RDS)

Delegamos la administración de la base de datos a AWS. El equipo TI deja de apagar incendios y administra servicios PaaS.

Seguridad (VPC)

Aislamiento de red total. La base de datos y los servidores viven en subredes privadas, invisibles y blindados frente al internet público.

Arquitectura PoC Validada (TO-BE Inicial)

Migración Aprobada

  • Capa Perimetral: El Balanceador de Carga (ALB) es el único punto de contacto con Internet.
  • Capa de Cómputo: Los contenedores corren en una instancia EC2 privada, oculta tras un NAT Gateway.
  • Capa de Datos: Servicio gestionado Amazon RDS para MySQL, restringido exclusivamente al Security Group del EC2.

Evidencia: Seguridad Perimetral y Redes

  • Segmentación VPC: Aislamiento estricto entre subredes públicas (ALB/NAT) y privadas (App/DB).
  • Instancias Ocultas: El EC2 fue desplegado sin IP pública.
  • Security Groups: El firewall de la instancia bloquea todo el exterior, aceptando solo el tráfico del ALB.

Evidencia: Cómputo y Base de Datos (RDS)

  • Zero-Trust: Puerto SSH (22) cerrado. Administración vía AWS Systems Manager (SSM).
  • Datos Seguros: Amazon RDS MySQL con acceso público desactivado y restringido por SG.

Evidencia: Balanceo y Enrutamiento (ALB)

  • Path-Based Routing: El ALB actúa como proxy inverso y punto de entrada único.
  • Target Groups: El ALB deriva tráfico solo si los contenedores reportan estado 'Healthy'.

Validación: La Plataforma Operativa

  • Disponibilidad Web: El eCommerce opera fluido a través del DNS del ALB.
  • Integración DB: Indicadores de "DB conectada" demuestran comunicación Backend → RDS.
  • Autoría Verificada: Despliegue automatizado validado con mis datos personales.

Próximos Pasos: Evolución Cloud-Native

Alineación al AWS Well-Architected

  • Escalabilidad Serverless: Migrar contenedores hacia AWS Fargate (ECS) para un Auto Scaling real.
  • Alta Disponibilidad: Implementar Amazon Aurora Multi-AZ para replicación síncrona.
  • Caché y Seguridad: CloudFront/S3 con protección DDoS mediante AWS WAF.
